Produce a batch

Before importing: check Zoho by hand for an existing Opportunity on each buyer. The Monitor never searches the CRM (D31) and the person importing is the only duplicate control. Every duplicate that reaches a batch is logged as a finding and counted at the week 14 gate.

Records already exported are never in a second batch. A range with nothing new in it still produces a batch, with a header row and no rows, so a run that found nothing is on the record.

Re-export a batch

Writes a batch that has already left out to disk again, under the same batch id and at the path the batch row records. It issues no new batch id, changes no record's stamp and produces no new batch: the records in it left once and stay left. The file is rebuilt from those records and refused unless it hashes to the sha256 the batch recorded, so what comes back is the file that left and not a new file wearing its name. A batch whose file is still on disk is checked and left alone.
